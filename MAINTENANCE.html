Website Maintenance Guide

Updating your site (3-step workflow)

cd ~/Documents/Playground/website

# 1. Edit any .qmd file (add a paper, update teaching, etc.)

# 2. Preview locally to check it looks right:
~/opt/quarto/bin/quarto preview

# 3. When happy, publish to the live site:
~/opt/quarto/bin/quarto publish gh-pages --no-prompt

Step 2 starts a local server (usually at http://localhost:4567) that auto-reloads when you save a file — so you can edit and see changes in real time.

Step 3 re-renders everything, pushes the built HTML to the gh-pages branch on GitHub, and your live site updates within ~1 minute.

Saving your source files

The publish command only pushes the rendered site. To save your source files (the .qmd files you actually edit), commit and push to main separately:

git add -A
git commit -m "description of what you changed"
git push

This is good practice so your source files are backed up and versioned. You don’t have to do this every time you publish, but do it regularly.

Good habits

  • Preview before publishing. Always run quarto preview and check the site in your browser before running quarto publish. Catches typos, broken links, and layout issues before they go live.

  • Keep source files on main. The gh-pages branch is managed automatically by quarto publish — never edit it directly. Your edits go in the .qmd files on main.

  • Commit often. After any meaningful edit session, commit your .qmd changes to main and push. This gives you version history (easy to undo mistakes) and a backup on GitHub.

  • One thing at a time. When updating, make one change, preview it, then move on. Easier to catch issues than batching many edits.

  • Update your CV PDF when you update the CV page. The CV page (cv.qmd) is a summary — the linked PDF (files/cv-sharon.pdf) is the full version. Keep them in sync. After recompiling your LaTeX CV, copy the new PDF into files/.

  • Check on mobile. After publishing, pull up your site on your phone once in a while. The CSS is responsive, but it’s good to verify.

Things to avoid

  • Don’t edit files in _site/. That folder is auto-generated by quarto render. Any changes there will be overwritten next time you render. Always edit the .qmd source files.

  • Don’t edit the gh-pages branch. Same idea — it’s managed by quarto publish.

  • Don’t commit _site/ or .quarto/ to main. These are in .gitignore for a reason. They’re build artifacts, not source files.

  • Don’t put sensitive info on the site. No home address, personal phone number, or private links. Your email and office are fine.

  • Don’t let it go stale. An out-of-date website is worse than no website. When you publish a paper, give a talk, or change roles, update the site. A quick “last updated” check every quarter is a good habit.

File reference

File What it does
_quarto.yml Site config: title, navbar links, theme
styles.css All custom styling (colors, fonts, layout)
index.qmd Home page (bio, photo, interests, news)
research.qmd Research descriptions
publications.qmd Papers and talks
teaching.qmd Teaching experience
cv.qmd CV summary + link to PDF
diversions.qmd Non-academic stuff
images/ Your photo and any future images
files/ CV PDF and any future downloadable files
_site/ Auto-generated output (don’t edit)
.gitignore Tells git to skip _site/, .quarto/, .DS_Store

Common tasks

Add a new publication

Edit publications.qmd and add a block:

::: {.pub-entry}
**Zhou, S.** et al. (2027). Your new paper title. [*Journal Name*]{.pub-venue}
[doi](https://doi.org/...){.pub-links} [pdf](files/your-paper.pdf){.pub-links}
:::

Add a new talk

Same file, under the Talks section — same format but without the link badges.

Add a news item

Edit index.qmd and add a line at the top of the News list:

- **Fall 2026** — Description of the news item

Change the photo

Replace images/main-photo.jpg with your new photo (same filename), then publish.

Change the accent color

In styles.css, find the :root block near the top and change --accent:

--accent: #2b6777;  /* teal — change this hex code */
